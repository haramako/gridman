## 観察

### 実装完了後に PR 作成を忘れるパターン（LIN-172/175 と同じ）

Run1 で DialogShell の Escape キーハンドラ（stopPropagation 問題）を修正したが、agent はコードを直しただけで PR を作成しなかった。Run2/Run3 で人間に指摘されて初めて PR を作成・謝罪した。これは LIN-172 / LIN-175 と同一の「PR 作成忘れ」パターン。

Run3 では agent 自身が「skill workflow が完全に実行されなかった」と原因分析している。以降の Run4/Run5 は単なる確認・クローズ応答で実質的な作業はなし。実障害はゼロ。

## 教訓

1. **PR 作成忘れは persistent な課題** — LIN-172, LIN-175 に続き 3 度目の発現。コード修正後のワークフローに PR 作成が確実に組み込まれていない。
2. **agent は原因を自覚できる** — Run3 では「skill workflow が完全に実行されなかった」と自己分析できている。自覚はあるが行動に反映できていない点が課題。
3. **AGENTS.md には既に PR 作成要件が記載済み** — ルール自体は存在するが、ワークフローの最後まで確実に実行される仕組みが必要。
