## 観察

### 複雑機能の高トークン実装

フィルタービューおよびユニオンビュー経由でのセル編集機能の実装タスク。4.2M トークンと大きく、ビュー越しの編集は元テーブルへの変換ロジックが必要で、既存のフィルター・ユニオン実装を広範に読んで実装したと考えられる。1回で完了しており品質は問題なかったが、高コスト。

## 教訓

1. **ビュー越し編集は事前設計が重要** — フィルター行とユニオン行で元テーブルへのマッピング方法が異なる。issue に「ビュー → 元テーブル座標変換の仕様」を記載するとエージェントの探索コストが下がる。
2. **4M トークン超の実装は分割の余地がある** — フィルタービュー経由編集 / ユニオンビュー経由編集を別 issue に分けると1 run あたりの負荷が下がる。
