### platform-artifact 判定

最新 run（runs[0]）は `status == "completed"` のため、platform-artifact には該当しない。ただし runs 配列の最古（runs[5]）が failed かつ `trigger_summary == null` であり、quota 切れによる失敗。

### quota-recovery パターン

Run 2 の "ping" は quota 回復後の手動再開チェックに相当する。実際には ping によって正常に再開・完了している。

## 教訓

1. **使用量上限が切れた場合は回復後に ping で再開できる** — 今回は quota 回復後の ping で正常に再開され、PR 作成まで完了した。
2. **bare ping の連鎖は避ける** — Run 3・5・6 はすべて "ping" だけで実作業なし。kanade-opencode がループ的に ping を送っており、エージェント間のメンション設計を見直す余地がある。
3. **コンフリクトは main の更新頻度が高い場合に発生しやすい** — Run 4 で2回の rebase が必要になった。並行して複数のlint修正PRが進んでいた影響。
