total_tokens が 10,532,185 と 10M 超え。1154 行のファイルを分割する作業がコンテキストを膨らませた主因。結果として `useColumnResize.ts`・`useVirtualScroll.ts`・`useKeyboardNavigation.ts` の3フックに切り出し、本体を 1154 行 → 384 行に削減して PR #32 を作成。

### 対策の現状

## 教訓

1. **使用量上限後の ping は複数回必要になりやすい** — クォータ回復を確認する run と実作業 run が別になるため、回復後に「続けてください」の明示的なトリガーを送ると確実。
2. **大規模ファイル分割は sub-task に分割してから着手する** — 1000 行超のリファクタは 10M トークンに達しやすい。AGENTS.md の「変更対象ファイルが 10 個以上 or アーキテクチャ設計が必要 → 中止・分割依頼」ルールを守ることで防止できる。
