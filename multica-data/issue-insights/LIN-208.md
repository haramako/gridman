# LIN-208: 複数セルのコピー後のUNDOが１つずつ処理される

## 観察

Run1で実作者是完了したが、mainブランチに直接コミットしてPR作成をスキップ。Run2でPR作成の指示があったがcancelled。Run3でユーザーからコミットミスとrevert試行の経緯を問われ、説明とPR作成（#71）を完了。Run4では外部レビューでバグが指摘され、別agentで修正コミットが作成されたためcancelled。

根本原因は `applyPastedText` と `handleCut` が `updateCell()` をセルごとに個別呼び出していたこと。既存のバッチメソッド `updateCells()` が `CompositeCommand` で単一undoに対応していたが使用されていなかった。

## 教訓

1. **PR作成の徹底** — 実装完了後は必ずPRを作成すべき。main直接コミットはワークフロー違反。
2. **既存バッチメソッドの活用** — `updateCells()` のような既存のバッチ処理メソッドを積極的に使うことで、UNDO/REDOの整合性を確保できる。
3. **E2Eテストの重要性** — 複数セル操作のUNDO挙動はE2Eテストで確認すべきだった。
