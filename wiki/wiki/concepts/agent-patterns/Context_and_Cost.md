# コンテキスト肥大化と高コストパターン

→ [[concepts/agent-patterns/index|Agent Patterns]] の一部

## 概要

`context-overload` は 50件中 8件で観察された **最多パターン**（2026-05 時点）。
大規模・横断的な実装タスクでコンテキストが肥大化し、2.6〜10.5M トークンを消費する。
AIの品質問題ではなく**issue 設計の問題**として改善できる。

**該当 taxonomy**: `context-overload`

| **LIN-171** | **SpreadsheetGrid.tsx の分割（1154行）** | **10.5M** | **大規模ファイル分割・複数 run 失敗** |
| LIN-16 | [TML] 入力検証強化 | 7.1M | 多数の再実行・広範な env 問題 |

## 削減戦略

### 1. ターゲットファイルを明示する

悪い例:
```
Undo/Redo を実装してください。
```

良い例:
```
Undo/Redo を実装してください。
対象ファイル: src/store/gridStore.ts, src/commands/EditCellCommand.ts
他のファイルは読み込み不要です。
```

### 2. 設計フェーズを分離する

「設計を先に見せてから実装」と明示すると、エージェントが全コードを読む前に
方針を確認できる。LIN-44 の指示（「まずコマンドバッファによる履歴保存からプランしてください」）
は良いパターン。

### 3. 開放型サーベイを絞り込む

悪い例:
```
バグをリストアップして issue を作成して。
```

良い例:
```
グリッド操作（セル選択・編集・コピペ）に絞ってバグをリストアップしてください。
まずコメントにリストを書いて確認してから issue を作成してください。
```

### 4. 大きなタスクを分割する

| 元タスク | 分割案 |
|---------|-------|
| SpreadsheetGrid.tsx 分割 (10.5M) | useColumnResize / useVirtualScroll / useKeyboardNavigation を個別 issue に（LIN-180/181/182 で実施済み） |
| ビュー経由での編集 (4.2M) | フィルタービュー編集 / ユニオンビュー編集 |
| StyleSheet キャッシュ改善 (5.4M) | キャッシュ上限追加 → テスト追加（別 issue） |

LIN-171 は 1154行の巨大ファイルを一度に分割しようとして 10.5M トークンを消費し、2 run 失敗した。
その後 LIN-180/181/182 として sub-task 分割され、それらは親タスクの作業内で実行なしに完了している（run=0）。
**大きなリファクタは sub-task 分割後に個別実行するより、1 つの PR で一括処理する方が効率的なことがある。**

## メトリクスへの影響

`context-overload` タスクは実行回数 1 であっても高コスト。
issue ごとのトークン消費を追跡する際は、`total_tokens > 2,000,000` のケースを
別カテゴリ（「大型タスク」）として集計すると実態が見えやすくなる。
